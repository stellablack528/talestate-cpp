# 重要记忆、常驻状态与睡觉修复

已定位阻塞链：上一版 Session._sleep 在推进前调用 settle_npcs，对每位有未结算对话的 NPC 再请求模型，要求较长的日结 JSON；任一回复无法解析便回滚整晚。实际服务的原始返回没有保存在仓库，不能断言具体是哪一种格式错误，但阻塞发生在这一链路。

本轮移除睡觉中的全部 API 请求与 JSON 解析，仅按已存的结构化计划本地结算。普通到期事务完成，依赖玩家或正式交付的计划保持待办，不改变物品/任务/奖励。家中新增“消磨时间到晚上”，直接到 20:00，之后可无 API 睡到 08:00。

NPC 长期记忆移除详细 conversations 和包含原文的 dialogue 观察。只保存重要 who/when/what/来源、计划、设定变更与亲历事件。详细对话作为玩家显示记录单独保存在 dialogues/ 和 session 顶层，不进入 NPC 的长期记忆；仅近期六轮用于接话。旧存档加载时分离旧记录，保留人物设定、重要记忆、游戏进度与玩家聊天显示记录。

每次真实对话要求模型返回 activity 常驻状态，保存到当前人物 daily_state；打开人物窗口直接显示，不调用模型刷新。只有尚未提示的相关任务阶段才主动请求 AI，重访/读档不重复。常驻状态缺失会在当次交互报错，避免声称已更新却未保存。

正常对话请求显式使用 JSON 对象模式，解析首个完整 JSON 对象，并单独报告截断；没有添加伪造回复或静默模拟模型回退。普通 API 交互失败仍不提交进度。

验证包含：常驻状态读档保留、非任务打开窗口 API 请求数为零、重要记忆文件不含原文、对话显示记录独立恢复、家中无 API 等到晚上/睡觉、个人计划结算不改变正式任务物品和人物私聊。本次还复制当前玩家最近存档，在故意让所有 API 调用抛错的环境中升级、回家、等到晚上并成功睡到次日；原 session.json SHA256 未改变。
