# NPC 连续记忆、文件权限与睡觉日结

本轮按用户反馈核验并修改实际游戏调用链。没有清空或推进用户存档。

## 核验结论

当前最近存档中，林岚/陈伯/周穗分别已有 10/3/7 条对话，4/1/2 条设定决策，三人的 characters 文件均存在。这证明此前不是完全没有写文件；决策中可能包含接受和拒绝，不能把决策条数当成修改次数。

发现的衔接不足：意图判定只读本轮输入、不读前文；角色回复的前文仅作为 JSON 内最近八条对话和关键词召回，并未以实际多轮消息发送；重要承诺和当天个人计划没有专门的长期状态，普通对话也不一定产生 npc_update。此前开场按每次到访去重，仍会反复发问。

## 实现

- 意图判定与角色回复读取同一个 NPC 的前文，兼容模型请求通过真实 user/assistant 消息承接对话。重要笔记、个人计划、近况和近日记录另外进入上下文。
- 提示明确区分“确实说过/答应过”和“已实际完成”，不能因为禁止伪造交付就否认谈话中已有的约定。
- 仅有相关任务新阶段才主动搭话；同一事项的提示标记写入存档，重访或读档不重复，无任务不自动询问。
- 角色可返回 memory_update 保存 notes、plans、activity；可继续接受/拒绝 npc_update 中的背景、性格、态度、目标和认知修改。
- 睡觉时按各 NPC 自己的记录结算当天生活，普通到期计划完成并刷新次日状态。依赖玩家或正式任务/物品交接的计划不凭空完成。历史个人计划可依据原对话事件补录。
- characters/<id>.json 与 npcs/<id>.json、完整 session.json 都落盘这些变化。原世界种子和源码不被模型直接修改；其他人物的记录不会被该角色改写。
- 日结任何请求失败，睡觉和所有候选人物更新均不提交。存读档一起恢复人物计划、长期笔记、近况、提示去重和日结记录。旧档缺字段时从初始值恢复，避免继承未来记忆。

## 验证

本地 HTTP 联调实际走 Provider：核查请求中包含上一轮 assistant 发言，再让模拟模型返回设定变更、记忆与计划，读取 characters 文件确认 attitude、notes、plans 已实际写入，Key 未进入存档。睡觉场景验证个人计划完成、等待玩家的计划保留、其他 NPC 记忆不变、物品/任务不被自动改写、日结失败不提交和回档恢复。也检查重访/重新打开存档不会重复任务询问。

这是实际请求结构与文件写入链的验证，未使用真实 API Key，不能据此保证第三方模型每次都正确提炼计划或遵循提示。角色完整原对话仍保留，未被摘要替换。
