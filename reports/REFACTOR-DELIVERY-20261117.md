# 本轮重构交付

主线现为 `runtime/talestate` + `clients/renpy` + `tools/world_builder` + `worlds`。旧 C++/Qt 实现完整保留在 `旧内容/原C++与Qt项目`，旧打包版保留在 `旧内容/历史游戏包`。没有提交或发布到远端仓库。

## 已实现

- 世界生成器：由右侧 Codex 完成，CLI、Python API 与 tkinter 窗口均可用；导入原文、预览或调用兼容模型、编辑草案、编译导出。不再固定三地点/三证据。
- 统一运行时：实体、位置、单件物品所有者、类型化动作、关联任务、奖励、时间、提交事件、会话存档。生成器的导出文件直接由运行时消费，不另造前端世界状态。
- NPC 记忆：每个 NPC 有世界初始文件与本局实际记忆文件，保存亲历和交谈、事件编号；存档恢复同时恢复记忆。模型上下文按人物读取最近信息和简单关键词召回，不截断磁盘完整记录。
- 可信显示：移动、物品归属、任务和奖励文本来自实际提交事件；模型只能选合法动作/条件台词 ID，不能直接提交完成事件或替换事实文本。
- Ren'Py：角色栏、背包、已探索人物/记忆、任务、自然语言输入、行动按钮、模型设置、存读档与世界切换。
- 媒体：统一清单引用背景、表情立绘、BGM、事件音效和台词语音。示例使用代码场景占位、人物字牌、原创合成 BGM/提示音；没有正式立绘或真人配音。
- 文件管理：生成副本、SDK、进度和缓存不提交；源世界只编辑根 worlds；启动/同步/打包分别有独立脚本。

## 实际验证

- 运行时三个关键流程检查通过：交付/归属/奖励/存档/记忆一致、模型伪造动作与台词不生效、生成器导出被同一运行时执行。
- 右侧 Agent 实际打开创作窗口并经按钮导出预览；已有媒体文件保留。
- Ren'Py lint 通过，真实渲染过游戏与设置界面，完成自动送药/交谈/保存流程。
- 官方 distribute 产出 `dist/TaleState-0.3.0-pc.zip`，解压包直接启动并完成同一界面流程，退出码 0，不依赖外部 Python/Qt/SDK。
- 没有用真实 API Key 测试真实模型服务。无 Key preview 明确是固定示例，不冒充模型生成。

## 入口

- `开始游戏.cmd`：开发环境自动同步后进入新游戏；SDK 不在时进入已打包版。
- `世界创作器.cmd`：独立世界创作窗口。
- `dist/TaleState-0.3.0-pc/TaleState.exe`：可直接运行的新分发包。
- `旧内容/启动旧版.cmd`：旧 Qt 版。

## 本轮边界

这是新架构的可运行主体，不是全部旧功能的一比一移植。旧日程、疲劳/生病、预约、旧存档迁移暂未迁入。人物目前使用条件台词，尚未开放任意生成的长篇 NPC 对话；这项取舍确保当前模型不能用自由叙述伪造奖励。未来扩展自由对话时仍需区分角色表达和世界事实。

初始记忆为历史认知，后续事件反映新状态；它不是自主思考系统。不同版本世界的存档暂不自动迁移。素材接口已接好，正式美术/配音需要创作者提供或后续制作。
