# 夜间 JSON 接口核查与每日记忆

本次更新替代此前 IMPORTANT-MEMORY-SLEEP 报告中的“睡觉完全不调用模型”和“仅最近六轮”方案。原存档未清空或推进。

## 可以确证与无法确证的原因

旧接口固定 max_tokens=1600，夜间却要求复杂的多字段结果。解析时字段缺失、空白正文与 JSON 语法错误合并成同一个 ModelError；旧的原始失败响应没有留存。因此可以确证输出额度与错误诊断设计有缺陷，不能确证玩家当时一定是截断、空白或哪处标点错误。移除 API 只能绕过阻塞，不等于找到了那次 JSON 错误的原因。

DeepSeek 官方 JSON Output 文档明确说明 max_tokens 不足会截断 JSON，且 JSON 模式可能返回纯空白，即使 finish_reason=stop：https://api-docs.deepseek.com/guides/json_mode/ 。

## 修复

- 保持 response_format=json_object 和明确 JSON 示例；默认输出额度4096，length时提高8192重试一次；空白时补充格式指令重试一次。其他语法/协议错误直接明确报告，不递归重试。
- 区分 HTTP 响应体非 JSON、choices/message/content 结构错误、空白 content、length 截断、JSON 语法错误行列、缺少对象。失败原始响应、finish_reason、usage、请求额度、阶段和 NPC ID 保存在本存档 diagnostics/。无 Key、请求头和完整请求日志。文件可能包含模型返回的角色内容，应作为玩家本地数据管理。
- 每个人物当日完整对话用于意图判断与角色接话；次日使用关键记忆。详细对话仅作为玩家历史保留。
- 每晚先完成睡觉与本地计划结算，再为有对话的 NPC 各发一个独立请求，结果仅 facts 数组、最多8条关键事实。没有对话不请求。原文不进长期记忆，正式任务/物品/奖励不能通过摘要改变。
- 失败标记 pending并提示原因，原对话继续供本角色接话；设置“重试记忆整理”或下次睡觉可再次整理。成功日去重，存读档恢复整理状态。

## 验证边界

本地真实 HTTP 适配器复现截断后成功、空白后成功、两次空白后停止、错误语法、缺字段与非JSON对象回复，验证错误分类、额度和有限重试、日志不含Key。游戏流程验证只处理谈过话的人物、超过六轮不丢弃、失败仍到次日、重试与成功去重、人物隔离及存读档。

没有留存历史真实模型失败响应，也未使用玩家 Key 发起收费请求，不能声称已还原那一次服务端返回。后续再发生时可通过诊断文件精确定位。
