# 最小探索世界包规格（阶段一）

输入是一段世界观文字。桌面端会要求现有地图生成器恰好提出三个地点和连通路线，再生成开局目标、三件证据、一处环境互动目标与 2–3 名 NPC。生成结果是正式 Story Package v1 JSON，可由 C++ 加载和校验。它用于探索、收集证据、使用证据与追问，尚未实现结局生成。底层转换函数也能从较大的地图草案沿起点路线选取三个连通地点。

| 创作内容 | Story Package 字段 | 阶段一处理 |
|---|---|---|
| 世界标题和背景 | `title`、`world_context` | 地图标题和原世界观文字，加上当前目标 |
| 玩家起点与开场 | `entry`、起点场景的 `entry_node`、`nodes[].text` | 起点来自地图，模型生成开场与目标 |
| 三个地点 | `chapters[0].scenes` | 地图中从起点可达的三个地点 |
| 双向移动 | `agent_routes` | 每条选中地图路线展开为两个方向 |
| 2–3 名人物 | `agent_npcs` | 模型生成姓名、所在场景、可询问话题和答复 |
| 初始关系 | `agent_npcs[].initial_relationship` | -3 到 3；运行时初始化到权威状态 |
| 场景与证据 | `agent_objects`、`agent_objects[].item` | 每个地点有可观察环境与一件可观察、可拿取的证据；物品进入背包、对象从场景移除 |
| 环境互动 | `agent_objects`、`agent_item_rules` | 模型提出目标、证据引用和结果文字；C++ 生成一次性 `use` 规则，检查物品与目标地点，成功后记录事件且不消耗证据 |
| 证据与事件追问 | `agent_npcs[].dialogue_rules` | 每位 NPC 有单件证据、两件证据组合和互动事件后的话题；条件由背包、事件和 NPC 记忆判定，首次成功才更新关系 |
| 基础行动 | `agent_routes`、`agent_npcs[].dialogue_rules`、`agent_objects`、`agent_item_rules` | 移动、交谈、观察、拿取、使用；证据可以按不同顺序取得 |
| 身份选择 | `world_spec.identities` → `variables`、`agent_actions` | 生成 2–4 个身份和属性修正；初始身份为空，只能选择一次，修正不得越界 |
| 属性与边界 | `world_spec.attributes` → `variables` | 生成 1–8 个整数属性及初始值、最小值、最大值；运行时行动依据上下限判断 |
| 成长与资源行动 | `world_spec.actions` → `agent_actions` | 生成 1–8 个通用行动；可声明场景、属性条件、花费、收益和一次性事件；C++ 编译条件及效果，拒绝资源不足、越界和重复一次性行动 |
| 预约活动 | NPC 阶段的 `appointments` → `agent_appointments` | 生成 1–3 项有 NPC、地点、开始分钟和时长的活动；玩家可预约、等待、到场，时间重叠或错过由 C++ 判定 |
| 两个结局 | 终局 `nodes` | **后续阶段**补充，此阶段不声称有结局 |

生成包可在桌面端保存为 `story.json` 并立即加载。地图确定后，生成器依次请求并检查通用规则规格、开局与对象、NPC 对话，最后合并成 Story Package。每一步分别允许模型根据错误修正一次，避免一次请求塞入全部内容而返回空结果。生成器会检查属性、身份、行动、对象、目标和人物引用，并通过现有 Story Package 校验；仍失败则不替换当前游戏。世界包 ID 从世界观、地图、规则规格和实际生成的内容计算；即使输入同一段世界观，只要生成结果不同，存档也不会误载入另一份世界包。API Key 不会进入世界包。

新增时间与约定规则后，生成包版本为 `0.5.0`。旧版探索包的存档不会被当作新版存档读入。

桌面端除 `story.json` 外，还会保存 `story.world-spec.json`，其中包含开局目标、起点、地点 ID 列表和下述 `world_spec` 对象，供创作者查看模型提出的身份、属性和行动规则。只有经 C++ 编译并通过 Story Package 校验的规则才成为权威状态和行动。自然语言中的世界设定仍是叙述素材，不自动成为可执行规则。

`world_spec` 最小结构如下；名称和内容由世界观决定，不绑定任何题材：

```json
{
  "attributes": [{"id":"stamina","name":"体力","initial":3,"min":0,"max":6}],
  "identities": [
    {"id":"scout","name":"斥候","description":"善于探索","modifiers":{"stamina":1}},
    {"id":"scholar","name":"学者","description":"善于研究","modifiers":{}}
  ],
  "actions": [{"id":"practice","name":"练习","description":"提升体力","scene":"hall","requirements":[],"costs":{},"gains":{"stamina":1},"once":false}]
}
```

`scene` 使用地图地点 ID，可省略或设为 `null`；`requirements` 支持 `eq`、`gte`、`lte`；`costs` 与 `gains` 是正整数映射，空内容用空对象。行动须实际改变至少一项属性。花费和收益作用于同一属性时，按净变化提交，但仍检查花费是否支付得起。生成器会拒绝不存在的属性或地点、重复 ID、超界初始修正与无状态变化的行动，并将错误反馈给模型修复一次。

当前验收是：两段不同题材的生成提案均能产出有效世界包；玩家能选定且不能重复更换身份，在指定地点执行属性成长行动；资源不足、属性到上限或地点不符时保持原状态，读档后身份和属性仍一致。玩家也能走访三个地点，以不同顺序观察和拿取对象；与环境目标互动会留下可保存的事件；NPC 可根据单件、两件对象及事件作不同回应。后续再扩展更多可组合的互动规则与结局条件。
