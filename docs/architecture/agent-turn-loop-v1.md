# TaleState 回合契约草案 v1

> 状态：分阶段实现。`assets/prompts/agent-turn-v1.md` 已在构建时编入 Agent 请求；每回合状态由 C++ 重新组装。重要话语候选、违法结算及契约版本存档仍待实现。

## 体验目标

世界从具体的开场处境开始：给玩家一个身份、地点、眼前的人和可以关心的事，然后留出探索、闲聊和自主选择的空间。剧情锚点由已发生的事触发，不按回合数强迫推进。支线是人物目标与玩家行为交汇后出现的机会；玩家可以拒绝、拖延或用别的方法处理，不要求清空任务列表。

普通聊天应得到符合人物身份、知识和情绪的自然回应。说话本身不自动加好感、送物品或开启任务。涉及人物目标、秘密、承诺、具体证据或越界行为时，Agent 可以提出候选后果；C++ 根据人物知识、现场条件和世界规则决定是否提交。创作者可以规定严厉的法律与失败条件，不能由模型临时宣布胜负。

## 三层信息

1. **版本化的静态回合契约**：模型的职责、输出协议、叙事节奏和禁止越权事项。修改后发布新版本；每个存档记录所用版本。
2. **创作者世界包**：地点、人物目标与已知信息、当地法律、资源、剧情锚点、结局条件及可用行动。新规则先进入候选区，经过引用和冲突校验后才能生效。
3. **每回合状态快照**：C++ 从已提交事件计算地点、时间、数值、背包、关系、人物认知、通缉状态和未了约定。模型只能读取允许该角色知道的部分。

每回合重新组装 `静态契约 + 世界包相关片段 + 当前可见状态 + 最近对话/相关记忆 + 可用行动`。**不在每回合覆盖静态 Markdown**；存档保存结构化状态和事件，方便读档、回放与排错。更改契约版本或世界规则时须有迁移策略，不能悄悄改变旧存档的含义。

## 回合处理顺序

```text
玩家自然语言
  → 意图分类：闲聊 / 观察 / 行动 / 时间推进 / 危险或违法尝试
  → Agent 提议：对话文本、结构化行动、可选的候选事件
  → C++ 预检：位置、目标、知识、资源、法律、身份和来源
  → 原子执行合法行动，拒绝或修复非法提案
  → 回合处理器：结算时间、消耗、伤害、目击、人物计划、约定与触发条件
  → 提交有类型的事件并更新权威状态
  → 依据提交结果生成叙述；下一回合重新组装可见状态
```

处理器必须幂等：同一回合或请求 ID 重试不能重复给奖励、重复扣资源或重复触发剧情。叙述不得声称未提交的事件已发生；若模型叙述与事件冲突，使用事实化的回退叙述并记录诊断。

## 对话与剧情触发

- `ordinary_chat`：NPC 可自由回应其已知范围内的话题；可以保留简短、有来源的对话记忆，但默认不改变关系、任务和世界事实。
- `significant_utterance`：玩家透露可核实线索、提出具体协助、威胁、承诺、告白等。Agent 提出候选事件，注明说话者、听者、地点、依据和希望改变的状态。引擎检查人物是否在场、是否听懂或相信、是否触及已有目标，再决定记录什么。
- 触发条件组合**语义提案与已提交事实**，不能只凭命中关键词。NPC 能说“不知道”“不信”“现在没空”，也能在日后有了新证据时改变回答。
- 关系变化应小而有原因。重复闲聊不刷好感；重要行动可以留下人物印象，但须记录来源。支线可以从 NPC 的需求自然出现，也可以自然消失，不强制变成任务清单。

例：玩家向守卫闲聊天气，守卫正常回应；玩家拿出已取得的带血徽记并询问失踪者，守卫先核对徽记来源，符合条件才提出调查失踪者的机会。玩家拒绝协助，世界照常运转。

## 节奏和成长

- 开场先给环境、人物与一件可关心的事；给玩家至少一次在当前区域自主观察或交谈的机会。紧急开局由世界包明确声明。
- 重大冲突需要前置迹象、原因和可追溯的触发事件。模型不得因为玩家走到新地点就立即揭开龙的真相或开启结局。
- 时间按行动成本与世界日历结算；闲聊、调查、旅行和训练花费不同。跳过时间时逐项处理跨过的约定、日程与危险。
- 成长来自通过规则的训练、经历和资源消耗；属性变化同时进入角色卡和判定状态。失败可以产生疲劳、损失或新线索，不必每次都推进主线。

## 违法行为与失败结局

世界包声明地点法律、守卫能力、目击条件、罪行严重度和失败条件。玩家尝试在城里袭击 NPC 时，先判定能否接近、是否成功、是否被看见，再由引擎提交受害、警报、通缉、追捕或逮捕事件。被捕、处决或死亡可按创作者规则进入 `game_over`；模型不能凭一句“我杀了他”直接抹掉 NPC，也不能无理由把所有世界都判成即时死亡。高戒备城镇可以把当街杀人设成几乎必然被捕并结束本局。

## 可扩展协议与验收

行动和事件应有 `type`、版本、稳定 ID、来源引用和允许修改的字段。新增行动类型需同时提供校验、结算、存档兼容和回放测试；未知类型明确拒绝。每次提交后输出 `accepted_events`、`rejected_proposals`、`state_delta` 与下一回合可见信息，供叙述器使用。

首批验收场景：

1. 新角色入城后可连续闲聊三次，NPC 回答自然，关系和任务不因次数自动增长。
2. 玩家透露一个**已获得**的独特线索，符合 NPC 目标时开启可拒绝的协助机会；没有线索时 NPC 不会假装知道。
3. 玩家训练、调查和旅行耗费合理时间与资源，开场冲突逐步显现，存档后后果一致。
4. 当街袭击 NPC 触发目击、通缉或城镇规则中的失败结局；未成功的行动不能让 NPC 死亡。
5. 同一输入在两种不同世界规则下得到各自合法的结果；叙述与提交事件一致。
