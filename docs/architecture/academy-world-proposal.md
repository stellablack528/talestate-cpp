# 魔法学院世界技术方案（审查稿）

目标是让作者保留一条完整主线和自己写好的支线，让 NPC 根据玩家行为改变剧情的推进方式，并让学院在玩家休息时继续发生变化。本稿沿用 Ren’Py、Python 运行时和本地存档，等待审查后实施。

## 现有底座和未攻克的问题

| 技术问题 | 当前能力 | 首版要补齐 |
| --- | --- | --- |
| 主线结构与手写内容保护 | 动作和任务可用前置条件及后续激活串联。创作器保留原文和需求映射 | 以稳定 ID 保存作者定义的章节、必经节点、结局和手写支线。生成区域内容时保护这些条目，并检查起点到各结局的通路 |
| 剧情证据 | 运行时能记录交付、战斗和教学，任务协议目前只接受实际交付 | 让剧情节点接受明确绑定对象的调查发现、战斗胜利、赴约和 NPC 决定，并支持多种达成方式与后续条件 |
| NPC 行动与事件 | 夜间会结算个人计划、组织同地点见面、更新近况并记录主动分享 | 用实际日程让角色按路线移动、见面、赴约或缺席。让事件在指定日期和地点可见，并有完成、错过和结束的结果 |
| 动态支线与新道具 | 夜间能生成使用已有物品的单段送货委托 | 支持生成信件或线索实例，并能引用它们串联后续任务。把作者物品、生成物品和任务引用一起读写进存档 |
| 规模与故障恢复 | 生成器一次请求输出全世界。夜间处理依次调用个人摘要和会面模型，读入全体 NPC 概况 | 分区域生成并合并。按当晚相关区域和人物取上下文，设请求与等待上限，避免重试后重复发物品、开任务或结算奖励 |

## 运行时与创作器怎么对接

**作者掌握必经节点，NPC 决定可采取的行动。** 每个主线节点写明前置条件、谁有资格参与、哪些证据可任选其一、哪些效果由作者指定。关键节点至少留一条可重试或可替代的路径。比如老师爽约后，玩家可以改约，也可以从图书馆查证。创作器检查引用、依赖环和示章的已知通路，再用实际游玩验证时钟、库存和行动条件。静态连通只说明结构有通路，实际可达性仍取决于玩法状态。

**对白、夜间统筹与作者脚本共用一条行动提交接口。** 作者脚本指现有结构化动作。运行时向 AI 提供当前可用行动与允许提出的少量提案类型，例如 `schedule_visit`、`share_fact`、`offer_quest` 和 `create_item`。提案引用人物、地点与原因证据的 ID。运行时核对权限、位置、时间、资源和作者限制，再把同一次行动的效果全部提交并生成事件，供下一阶段匹配证据。比如约定明天赴约只是一条日程，到了现场才产生赴约事实。对白根据提交结果叙述，拒绝的提案也给对白明确结果。

**随机事件从可发生的候选中产生。** 夜间先整理当天对话，再在候选状态结算固定日程、到期计划与当日事实，并在相关区域筛选有条件发生的事件。AI 可选候选、补写经过、提出允许的变体，或返回空结果。每个事件记录起因、参与者、地点、有效时段和状态。角色只收到自己亲历或经交流获知的信息。事件逾期时按规则结束或转成后续消息。首版调度优先处理近期行动、约定或作者剧情涉及的区域。AI 请求失败时保留当晚日期和已完成批次，恢复后继续同一晚。所有当晚工作成功后再进入次日。

**生成道具和支线一起保存。** 例如同学写了一封道歉信，运行时分配本局唯一 ID，记录作者、收件人、所属角色和来源事件。同一次提交创建信件及引用它的委托，保证读档时两者对应。玩家可接取、转交或错过。普通信件和线索允许自由命名和书写。装备数值、货币奖励及关键剧情道具引用作者定义的模板或规则。动态数据进本局状态，和任务、物品归属、NPC 记忆、事件及待办一起恢复。沿用模板内容哈希，旧档缺少新增字段时按空状态加载。

## 实施顺序与验收

1. **扩展剧情证据与行动提交。** 从现有交付、战斗、教学事件入手，加入调查和赴约的正式结果。先用作者写的两条替代路径贯通同一主线节点。验收时检查重复执行、事件条件不成立、保存后回读，确认节点和奖励只结算一次。
2. **接入夜间行动与动态内容。** 先在同一区域串通一次跨场景赴约和一次真实的信息分享，再让 AI 提出一条带自造信件的支线。分别验证接取、送达、错过、两位 NPC 可见知识的差别及断网后的次日结算。每晚的请求量、耗时和失败原因用实际数据记录，达到上限时结束本晚处理。
3. **接通创作器和魔法学院样章。** 作者先锁定主线节点和至少一条手写支线，生成器按区域补充课程、社交、探索和普通事件，合并后检查跨区引用及主线通路。示章用一个短学周作为规模假设，覆盖课堂、档案室、观星塔等少量地点。白天已有搜索、学习、战斗的机会，夜间可以改变次日的人物安排。
4. **用两条玩法验收后评估扩图。** 从同一开局分别走同学关系和独立调查，均完成观星塔章末目标。两次的在场 NPC、线索来源和后续机会应有可见差异。至少一条手写支线、一条 AI 支线、一次错过后的替代路径和一次读档后继续发挥作用。另用更大角色和日志规模测夜间等待、上下文体量及存档耗时，再决定扩展范围。

## 本次需要审查的设计取舍

- 主线的必经事实和章末结局由作者写定，NPC 可以分流过程、改变关系和创造新机会。作者也可在同一章节预先写多个结局和各自条件。
- 首版 AI 自由生成的实体以普通信件和线索为主。动态支线先覆盖调查、赴约和交付及其后续，再考虑其他类别。
- 学院是独立样章，沿用现有运行时。原海岸样例继续作为验证兼容性的基准。首版以一个短学周检验昼夜行为，规模目标随实测数据调整。
